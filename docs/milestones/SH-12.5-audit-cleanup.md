# SH-12.5 完了段階の整合性と境界テスト

状態: 実施中。前提: [SH-12](SH-12-self-hosting.md)。次: [SH-13](SH-13-unity.md)。

## 目的・変更対象

SH-01 から SH-12 までの監査で見つかった、固定 bundle の不整合、古い完了記録、SH-09 の境界テスト不足、SH-12 の入力変更テスト不足を解消する。対象は自己実行ドライバー、ホストテスト、固定情報、マイルストーン記録と上位文書である。新しい実行機能は追加しない。

## 実施手順

1. 後続段階が使用する bundle を一つに固定する。SH-01 の固定情報、各段階の結果、生成 manifest に異なる hash がある場合は、各 bundle を生成した commit と変更理由を記録し、現在の正典を明示する。
2. `verifyBundle()` で正典の bundle hash、runtime hash、実効 build property を照合する。別の bundle、古い inventory、別 bundle から生成した C# を混ぜると、後続処理を始める前に失敗させる。
3. SH-01、SH-07、SH-08 の終了 commit と、`README.md`、`IMPLEMENTATION.md`、各マイルストーンの状態を実際の履歴に合わせる。履歴上の測定値は上書きせず、どの bundle と環境の値かを区別する。
4. SH-04 から SH-07 の Unity Editor／Windows x64 IL2CPP 記録を点検する。version 管理する記録には Unity 版、入力・package・Player・ログの hash、成功 marker、実行 command を残す。元ログを確認できない記録は再実行するか未検証へ戻す。
5. SH-09 の reject import を実際に呼ぶ小型 fixture を追加し、module/name と引数を含む失敗を確認する。仮想ファイルへの短い write、read-back、read-only file、無効 fd、範囲外 iovec／pointer も、固定入力に対する正確な結果で検証する。
6. SH-12 に、class name だけでなく WASM の定数または命令 bytesを変更した入力を追加する。入力 hash、生成 C# の差、実行結果の差を確認し、同一入力の反復結果は引き続き完全一致させる。
7. 監査項目を機械的に確認する `node scripts/self-hosting.mjs audit` を追加する。この command は成果物を再生成せず、固定情報、終了 commit、必要な証拠ファイルと hash、負のテスト結果を検査する。runtime 全体を再生成する一括検証は SH-14 の `verify` に残す。

## 検証

```sh
dotnet build Wasm2Cs.slnx -m:1 -p:UseSharedCompilation=false --nologo
dotnet tests/Wasm2Cs.Tests/bin/Debug/net10.0/Wasm2Cs.Tests.dll
dotnet samples/Smoke/bin/Debug/net10.0/Smoke.dll
node scripts/test-build.mjs
node scripts/self-hosting.mjs audit
node scripts/self-hosting.mjs inventory
node scripts/self-hosting.mjs reference
node scripts/self-hosting.mjs generate
node scripts/self-hosting.mjs compile
node scripts/self-hosting.mjs host
node scripts/self-hosting.mjs hello
node scripts/self-hosting.mjs managed
node scripts/self-hosting.mjs translate
```

公開 package または Unity 入力を変更した場合は、`node scripts/pack.mjs`、`node scripts/test-package.mjs`、`scripts/test-unity.ps1` も実行する。Unity の過去記録を再取得する場合は、その段階と同じ Editor／Windows x64 IL2CPP 条件を使う。利用できない環境は未実行として記録し、過去の外部一時ディレクトリだけを根拠に完了させない。

- [x] SH-01 から SH-12 の状態、終了 commit、測定値、上位文書が実際の履歴と一致する。

## 非対象・失敗時の扱い

Unity 上の自己実行、SH-14 の一括再生成、CI 構成、runtime 自身の再変換は追加しない。巨大な bundle、生成 C#、Player を version 管理へ追加する必要はないが、再生成手順と SHA-256 は保存する。古い測定値と現在の測定値が異なる場合は、値を揃えるために書き換えず、対応する bundle と環境を記録する。
